# サイトの内容（コンテンツ）の編集

サイトに載せる文章・写真・戦績などは、すべてこのフォルダのファイルに書きます。
開発サーバー（`npm run dev`）を動かしていれば、保存するとすぐ画面に反映されます。

## どこを直すか

| 直したいところ | ファイル |
| --- | --- |
| 名前・肩書き・トップの写真・プロフィール写真 | `profile.md` |
| 自己紹介文 | `profile.md` の本文（2つ目の `---` より後ろ） |
| 基本情報・能力値・そうび・卓球歴 | `profile.md` |
| 戦績 | `results.yaml` |
| お知らせ | `news.yaml` |
| ギャラリーの写真・動画 | `gallery.yaml`（写真のファイルは `images/`） |
| スポンサー | `sponsor.yaml` |
| お問い合わせ先のメールアドレス | `site.yaml` の `contact_email` |
| フッターの SNS | `site.yaml` の `social` |
| サイト名・説明文（ブラウザのタブ・検索結果・SNS でシェアしたとき） | `site.yaml` |
| メニューの項目・説明文（コード側） | `src/data/site.ts` |

各ファイルの先頭に、項目の意味と書き方をコメント（`#` で始まる行）で書いてあります。

## ページを「準備中」にする

中身がまだないページは、自動で「準備中（Coming soon）」の表示になります。トップのメニューのカードも、点線の枠で「Coming soon」と表示されます。

| ページ | 準備中になるとき |
| --- | --- |
| 戦績 / お知らせ / スポンサー | `results.yaml` / `news.yaml` / `sponsor.yaml` の項目を全部消したとき（コメントの行は残してよい） |
| ギャラリー | `gallery.yaml` の `photos:` と `videos:` の中身が両方とも空のとき |
| お問い合わせ | `site.yaml` の `contact_email` が空のとき |

準備中のページは、検索結果に出ないようにしています。

## 書き方のきまり

- **日付**: `2026-08-24` / `2026-08` / `2026` のどれか。日がわからなければ月まで、月もわからなければ年だけでよい。
- **なくてもよい項目**: 行ごと消すか、値を空にする。
- **並び順**: 戦績・お知らせ・卓球歴は日付で自動で並ぶ。それ以外（写真・動画・スポンサー・基本情報・そうびなど）は書いた順。
- **自己紹介（`profile.md` の本文）**: Markdown で書ける。空行で段落が分かれ、`**太字**` や `[リンク](https://...)` も使える。
- **記号を含む文字**: 文字の途中に `: `（コロンとスペース）や ` #`（スペースと #）があると YAML の記号として読まれてしまうので、`"` で囲む。
  例: `title: "決勝: 3-2 で勝利"`

### 写真

写真のファイルを `images/` に置き、`src` にこのフォルダからの相対パスを書きます。
撮ったままの大きな写真で大丈夫です（公開用のサイズ・形式にはビルドのときに変換されます）。

```yaml
image:
  src: ./images/match.jpg
  alt: 試合中にボールを打つ太田輝 # 写真の説明（画面の読み上げなどで使う）
  position: 50% 20%               # 切り抜いたときにどこを見せるか
```

`position` は、正方形などに切り抜いて表示するときに写真のどこを見せるかを「横 縦」の順で書きます。
省略すると真ん中（`50% 50%`）です。`50% 0%` なら上の端、`0% 50%` なら左の端に寄ります。

## 書き間違えたとき

必須の項目が抜けている、日付の形が違う、写真のファイルが見つからない、といった場合は、
`npm run dev` / `npm run build` のときに、どのファイルのどの項目かをエラーで教えてくれます。

```
[InvalidContentEntryDataError] results → results data does not match collection schema.
  1.date: 日付は 2026-08-24 / 2026-08 / 2026 のどれかの形で書いてください
```

`1.date` は「上から2番目の `date`」という意味です（番号は 0 から数えます）。

## 公開

`npm run build` で `dist/` に公開用のファイルができます。
Cloudflare に GitHub のリポジトリをつないだあとは、main ブランチに push すると自動でビルドされて公開されます。
